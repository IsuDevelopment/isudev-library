# IsuDev Library — guide for coding agents in consuming projects

You are working in a theme or site that **uses** the IsuDev Library plugin
(`isudev-library`). This file is the index: read the rules below, find what you
need in the catalog, then open that block's or extension's `README.md` or the
guide it links to before writing code. If you are working **on** the plugin
itself, its repository's `AGENTS.md` is the guide instead.

To make this file discoverable in a project, run from the project root:

```bash
php path/to/isudev-library/bin/agents-init.php          # write/refresh
php path/to/isudev-library/bin/agents-init.php --check  # CI: fail when stale
```

It copies this guide to `.agents/vendor/isudev-library.md` (links rewritten to
the installed plugin) and adds a short marked block to `AGENTS.md` (and to
`.github/copilot-instructions.md` / `.cursor/rules/` when those already exist).
Re-running it after a plugin update is safe.

## Rules

1. **Never edit the plugin.** Change behaviour from the theme: `isudev.json`,
   hooks, theme files. A plugin update overwrites edits.
2. **Configuration is `isudev.json` → `library`.** Enable or disable blocks
   (`library.{block name}.enabled`) and extensions
   (`library.extensions.{slug}.enabled`), set block variations and per-block
   keys documented in each README. The file is shared with other `isudev-*`
   plugins; only the `library` key belongs to this one. Example:
   `isudev.json.example` in the plugin.
3. **Blocks render in PHP.** What a block outputs is decided by `render.php` and
   its hooks; there is no client-side rendering to patch. Style it from the theme
   with the class contract in its README.
4. **Hooks are prefixed `isudev_library/`** (PHP) and **`isudevLibrary.`** (JS).
   The catalog lists every one with the doc that shows an example.
5. **Extensions are off by default.** Turning one on changes the admin or the
   front end immediately; read its README first.
6. **Editor UI comes from `@isudev/gutenberg`.** When the theme adds editor
   controls next to these blocks, use that package (link, media, post picker,
   responsive controls), not hand-rolled ones.
7. **Theme files the plugin reads** (each documented in its guide):
   - `isudev.json` (theme root)
   - `isudev/cards/{slug}.php` and `parts/card-{slug}.html` — post card templates
     ([post cards guide](../guides/post-cards.md))
8. **When a block renders nothing,** its README's *Troubleshooting* section says
   why. Check that first.
